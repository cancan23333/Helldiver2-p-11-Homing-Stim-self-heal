# Homing Stim v1.0.12

作者：cancan2333（基于 Guided Rounds v1.8.0 改造）

把 **P-11 治疗剂手枪**改造成锁定**友方单位**的制导武器。弹丸出膛后自动追踪
**潜兵**与 **SEAF AI NPC**，并且优先飞向受伤的目标。

> **它和 Guided Rounds 的关系**：锁定逻辑、制导组件、屏幕 UI、掩体射线全部沿用
> Guided Rounds v1.8.0 已经跑通的实现，只改了两件事：
> **① 枪械固定为 P-11 治疗剂手枪；② 锁定对象从敌人换成友军。**

## 「即锁 / 子弹穿墙」这个选项已经删除

它被删掉有两个原因，都是对的：

1. **它做不到名字承诺的事。** 引擎**没有任何字段**可以让弹丸无视碰撞，所以子弹依然会撞在
   掩体上。我把能查的地方都查了：SDK 允许写的弹丸字段只有 `velocity`、`mass`、`drag`、
   `gravity`、`lifetime`、`diameter`、`penetration_slowdown`、`pellet_count`、`type`、
   `direct_damage`、`impact_explosion`、`expiry_explosion`；Guided Rounds 逆向出的弹丸
   偏移是 `+0x18` 口径、`+0x20` 速度、`+0x24` 质量、`+0x28` 阻力、`+0x2C` 重力、`+0x3C`
   伤害、`+0x90` 爆炸 —— **两边都没有碰撞过滤**。唯一沾边的 `penetration_slowdown` 管的是
   穿甲，不是穿墙。
2. **它和「掩体判断」功能重叠。** 去掉「穿墙」这部分之后，它剩下的作用（优先锁打得到的目标）
   本来就该是「掩体判断」的职责，两个开关并排只会让人不知道该开哪个。

所以现在**掩体判断是唯一控制掩体的开关**：开启（默认）就不锁掩体后的人，关闭就锁。

## 射击时自我恢复

**真实开枪就给自己回血。** 上一次的实现走错了路（见下方「上一版为什么失败」），这一版改用
现成的、已验证可行的机制 —— 也就是 `P-11-Self-Heal-v1.0.4` 用的那套：

- **触发是「真的开了一枪」**：挂运行时的 `player_fired` 事件，它统计的是游戏自己的
  `projectiles_fired`，而且**按武器来源分开计数**。所以换弹、拔枪、空扳机都不会回血，
  也不需要扫内存去发现「开了一枪」。
- **回血走游戏自己的函数**（`Player:heal` → 游戏内部 `AddHealthFraction`）：
  **自动封顶到最大血量**，倒地或死亡时会被拒绝。**不写任何内存、不改任何游戏数据。**
- **连射不会瞬间满血**：运行时每秒轮询 10 次统计，一阵连射会合成**一个带计数的事件**，
  `heal_per_event`（一个事件最多付几次）和 `heal_cooldown`（两次之间至少几秒）就是两道闸。

### 设置

菜单里有三个：**射击时自我恢复**（总开关）、**自我恢复量（最大血量%）**、**自我恢复冷却（秒）**。
其余在 cfg 里：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `self_heal` | 0 | 总开关 |
| `heal_percent` | 35 | 每次真实射击回**最大血量的百分之多少**（约等于一针兴奋剂） |
| `heal_amount` | 0 | 改用**绝对血点**；0 = 用上面的百分比，大于 0 时覆盖它 |
| `heal_limbs` | 1 | 同时修复**部位损伤**（头/胸/双手/双膝）。需要运行时有 `hd2.actions.heal_limbs`（HD2Runtime 0.30+）；没有会在日志里说 |
| `heal_cooldown` | 0.5 | 两次治疗之间至少隔多少秒 |
| `heal_per_event` | 1 | 一个已射击事件最多付几次（连射想回得更快就调 2–3） |

**为什么默认用百分比而不是固定血点**：`Player:heal` 收的是**血点**，而「多少血点算多」取决于
游戏给本地玩家用的血量刻度 —— 固定写 25 点，可能是三分之一血，也可能是四十分之一。
日志里会同时打出**实际回了多少**和**最大血量**，所以这个数值可以照着日志调。

### 上一版为什么失败（留个记录）

我上一版做的是「一次射两发，其中一发引导回来扎自己」。它**不可能成功**，有两个独立的引擎原因：

1. **转向率不够。** 租来的 P-92 法令制导组件约 **30°/秒**、弹速约 90 m/秒。弹丸一出膛是朝前
   飞的，以这个转向率掉头需要好几秒、飞出去几百米 —— 「飞一小段就拐回来」在物理上做不到。
2. **引擎把射手排除在自己弹丸的碰撞之外。** 所以弹丸根本打不到开枪的人。

这两条都是引擎事实，不是能绕过去的 bug。所以现在改成**不依赖弹丸**的做法。

## 「子弹穿墙」到底做了什么

它**不是**真的让子弹穿过几何体，而是**跳过锁定流程**：

- 出膛生效时间 `bind_delay` 归零 → 弹丸一存在就立刻绑定目标，没有「等引擎锁」的过程；
- 索敌时**忽略锥角**，只要在锁定距离内就选；
- 索敌时**忽略掩体判断**，墙后的目标照样锁。

绑定之后，转向仍然由**游戏自己的制导组件**完成，所以弹道手感是原版的。
名字叫「穿墙」是因为实际效果就是墙后满血队友也能被直接命中。

## 工作原理

1. **租用制导组件**：把 P-11 自己的 `ProjectileWeaponComponentData` 行复制到私有槽位，
   再把 **P-92 法令弹丸实体**写进副本的 `+0x28 projectile_entity`。共享资源行**一个字节都不动**。
   如果 `+576` 上带着备用射击模式索引，租用会被**明确拒绝并写日志**——那种行不能改。
2. **绑定目标**：扫描健康表拿到候选单位（当前血量 / 最大血量 / 状态 / 骨骼节点），
   按上面的优先度打分，然后往索敌管理器的 net 记录写目标并 `publish` 目标字段。
   这一步**与阵营无关**，所以改成锁友军不需要碰绑定代码。
3. **画 UI**：范围环按相机视场角投影成屏幕圆；锁定标记和方框是原版法令的素材。

## 范围环为什么可能看不见

范围环的屏幕半径是：

```
半径 = tan(锥角) × (屏幕高/2) ÷ tan(视场角/2)
```

所以**只有锥角小于当前视场角的一半时，圆环才留在屏幕内**：

| 锥角 | 腰射（视场约 60°） | 开镜（视场约 30°） |
| --- | --- | --- |
| 15°（出厂值） | 251 px，正常 | 540 px，正好在屏幕边缘 |
| 20° | 340 px，正常 | 734 px，**跑出屏幕** |
| 30° | 540 px，刚好在边缘 | 1164 px，**完全看不见** |

**所以「开镜时看不到范围环」几乎都是锥角调太大。** 出厂值 15° 在所有视场角下都看得见，
而且在 10 米处仍然覆盖 2.7 米半径，足够抓身边的队友。想让圆环在开镜时也正常显示，
把「锁定范围锥角」调到 15 或更小。

## 修复记录

**v1.0.9**

文档更正版：v1.0.8 里我把两件事说错了（`require_assets` 需要 tick、以及共享行会影响 SEAF 治疗枪），代码行为不变，说明已改正，并新增「联机时别人会看到什么」一节。

**v1.0.12 —— 索敌普查改为**默认开启**，并修掉 SEAF 的阵营判断不对称**

看了你的日志之后发现两件事：

1. **我用来回答这个问题的日志根本没被写出来。** 「哪个实体类型被哪一道关卡拒绝」那行
   `SCAN not-admitted entity types` 之前**锁在 `debug=1` 后面**，而你的 cfg 里是 `debug=0`
   —— 所以日志里一行都没有，我无从判断。现在这组普查**默认就开**，每 10 秒一行，
   并且顺带带上制导管理器里的弹丸数（`seek active=`）和这段时间的绑定次数。
   以后遇到「某个单位锁不上」，日志里会直接打出它的哈希。

2. **SEAF 的阵营判断有个不对称。** 潜兵那边**读不到阵营行就算通过**（白名单已经担保了它），
   但 SEAF 那边**读不到就当拒绝**。可是 `faction_of()` 读不到只是说明这个实体**还没进阵营表**
   （刚刷出来的单位就是这样），并不是「它是敌人」的证据——
   于是**刚刷出来的 SEAF 会被直接丢掉**。现在 SEAF 也改成「白名单是身份判据，
   阵营掩码只在读到时做二次确认」。这样是安全的：敌人只有在其实体类型**正好是某个 SEAF
   身体哈希**时才能混进来，而它显然不是。

**日志里的旁证**：整份日志里，**v1.0.11 新加的那 10 个 SEAF 类型（MK3–MK8、`SEAF`、
`SEAF（城市）`、`SEAF 机枪手`）一次都没有被绑定过**，而所有绑定过的名称都来自我原来的 10 条。
这既可能是那些型号没出现，也可能是它们被某道关卡挡掉了——第 1 条改完之后就能分辨。

**另外注意**：你最后一次游戏（00:38–00:40）的日志是 `0 bind(s), 0 self-heal(s)`，
也就是整场**一次都没绑定**，而准心那边显示 `drawn_locked`（确实锁上了目标）。
这说明**弹丸可能压根没进制导管理器**——新的 `seek active=` 就是用来确认这一点的。

**v1.0.11 —— 补齐 SEAF 白名单（「个别的 SEAF 不锁定」）**

**原因**：SEAF 白名单是我**手工从资源表的一个区块**里抄的 10 条，而整个表里其实有 **20 个 SEAF 身体**。少了的那 10 个正好散落在**另一个区块**：
**SEAF MK3 / MK4 / MK5 / MK6 / MK7 / MK8、`SEAF`、`SEAF（城市）`、`SEAF 机枪手`**，以及**第二个 `SEAF MK2` 哈希**（表里确实有两个不同的 MK2）。这些哈希从来没进过白名单，所以**它们根本进不了候选**——这就是「个别的 SEAF 不锁定」。

**现在**：白名单改成 **20 条**，覆盖资源表里每一个 SEAF 身体。名称含 `SEAF's …` / `SEAF的…` 的是**装备**（它的解放者、SMG、MG-43、EAT-17、治疗枪、手雷、背包），**不是单位**，所以不收——单位的实体类型不会是装备的哈希。

顺带删掉了 `SEAF_BY_HEX`：那张表声明了**从来没人读**，是同一份名单的第二份拷贝，也就是第二个会走样的地方。

**新增交叉校验测试**：它把源码里的白名单**读出来**，再**独立地**从资源表重新推导一遍，两边比对。所以以后少一条、或者哪个字节抄错，都会直接测试失败，而不是变成你的 bug 反馈。变异测试确认：把 MK3–MK8 删掉（还原原来的遗漏），测试立刻报出这 6 个 MISSING。

**v1.0.10 —— 绿色方框的**真正**原因（参考 Guided-Rounds v1.8.5）**

我前两次都在猜「手上是不是 P-11」判错了，**方向完全错了**。`Guided-Rounds-v1.8.5` 的更新日志把原因写得很清楚（第 25、26 条），而且它对症状的解释和你的观察逐字吻合：

> 「目标离开锁定范围时会正常消失，但锁着的时候切武器就一直在——前者走的是另一条路径，`reset` + 一条全透明线 + `dispatch`，那条一直是好的。」

**真正的原因**：世界方框是一个 world-space line object。丢弃它时只调了
`World.destroy_line_object`，然后**不管成功与否都把句柄置空**。这个调用一旦没有真的把对象从
画面里拿掉（或者那一刻 `main_world()` 是 nil），方框**就永远留在屏幕上、而且再也没有任何
代码能碰到它**。而「手上是不是 P-11」那道闸门**一直是好的**——它正是切武器时去调
`drop_lines` 的那段代码；坏的是 `drop_lines` 本身。

**照 v1.8.5 移植了三处**：

1. `clear_line()`：先用**已知可靠**的方式把方框变不可见（`reset` + 全透明零长线 + `dispatch`）；
2. `drop_lines()`：**先隐藏**，再尝试交还引擎，**只有真的交还成功才放掉句柄**；
   （连续失败 120 次且已不可见时才放手，避免坏掉的 destroy 被无限重试）
3. `ctx.target_at` **帧戳**：方框只在锁定「新鲜」（60 帧内）时绘制，
   过期就隐藏——这样方框不可能比 mod 自己的追踪活得更久。

**同时删掉了我自己加的两套启发式判断**（wielder 槽位读取、枪口/相机夹角兜底）。它们是为了这个 bug 加的，方向错了，而且**有真实风险**：槽位被回收或键猜错时会报「不在手上」，把**正常工作的准心藏起来**。现在恢复成参考实现的判断方式。

   （`metadata.json` → `api.classes.HD2Watch` = status / result / error / cancel / attempts /
   max_attempts / last_transient），**运行时自己每 0.25 秒轮询一次**包状态
   （`docs/asset-loading.md:67-69`）。参考实现里那个 `aw.tick` 是**为更老的 API 写的防御性代码**。
   （那个带保护的调用我保留了——它不花钱、对老运行时有用——但它不是加载包的原因。）

   真相是：**加载是本机的**，SDK 原文（`asset-loading.md:161-166`）：
   > "Loading is local. Each client loads the loadouts it knows about. A host with the mod
   > loads the package for itself only. Clients without the mod still see whatever their own
   > game resolves, and may still see a missing asset for an object whose authority is the host."

   而且这个实体**是会同步到对端的**（`support-weapon-api.md:372-374`：换出来的实体由射手生成并同步，
   所以每个机器都得自己备好它的资源包）。**结论：只要换了投射物实体，没装本 mod 的机器看到问号就是
   结构性的，本机做任何事都改不了。**

3. ~~锁定方框切武器后仍在——再修一次~~ —— **这一条的方向是错的**，见 v1.0.10。
   我当时以为「手上是不是 P-11」判错了，那是错的诊断。

## 日志里怎么排查「锁定 UI 不显示」

`%LOCALAPPDATA%\HomingStim\HomingStim.log` 里这几行直接说明卡在哪一步：

| 日志行 | 含义 |
| --- | --- |
| `READY - P-11 Stim Pistol located` | 枪认出来了、租约已生效 |
| `LEASE REFUSED: ... alternate settings index` | P-11 的设置行带备用射击模式，无法租用（目前未见） |
| `RETICLE hand weapon: type=... -> lock UI ON/OFF` | UI 模块认为手上拿的是不是 P-11 |
| `RETICLE ... status=no_stingray` / `no_ui_world` | 引擎的屏幕 GUI 接口没拿到，画不出来 |
| `AVATAR local entity type ...` | 潜兵判定用的自身实体类型 |
| `SCAN seen=… live=… -> identity=… -> health=… -> faction=… -> usable=…` | 索敌普查（需 `debug=1`）：每一步筛掉了多少，卡在哪一关一目了然 |
| `SEEK header count=… active=… authority=…` | 制导管理器表头（需 `debug=1`）。**联机时关键**：如果 `authority` 不是本机，说明制导可能由主机驱动，客机的绑定会被忽略——这一行就是用来确认这件事的 |
| `SCAN not-admitted entity types: …` | **被身份判定拒绝的实体类型**。如果有个哈希每次都出现，那很可能就是别的玩家的化身用了和本地玩家不同的实体类型——把它发我 |
| `MIGRATE cone_deg` | 旧 cfg 的 30° 已被自动改成 15° |
| `SELF-HEAL subscribed to player_fired` | 自我恢复已挂上事件，可以回血 |
| `SELF-HEAL could not subscribe` / `HD2Runtime is not installed` | 自我恢复不生效，需要 HD2Runtime |
| `SELF-HEAL +N of M max` | 每次回血的实际数值（需要 `debug=1`） |

## 联机时别人会看到什么（重要的结构性限制）

**换了投射物实体，就必然要求每台机器自己备好它的资源包。** 因此：

| 机器 | 看到什么 |
| --- | --- |
| **装了本 mod 的机器** | 正常：弹丸有模型和材质 |
| **没装本 mod 的机器** | **粉色问号**（缺资源占位符），除非该机器上有人**正带着 P-92 法令手枪**（那样 `smart_pistol` 包会常驻） |

这不是本 mod 的 bug，也**不是本机可以修的**：SDK 明确写了加载是本机的
（`asset-loading.md:161-166`），而实体又是由射手生成并同步的
（`support-weapon-api.md:372-374`）。SDK 唯一的对端方案（synced asset loading）是
**仅离线验证、未开放给 mod**，而且要求对端运行版本与目录哈希都匹配。

**想要所有人都看到正常弹丸，只有两条路：**

1. **让队友也装本 mod**（并启用 HD2Runtime）；或让某人**带着 P-92 法令**进局；
2. **不换投射物实体**——改用 HD2Runtime 自己的 `hd2.projectiles.homing()`（它靠写弹丸速度转向，
   不动实体，所以那个 318 弹丸的模型天然正常）。**代价很大**：它**只能锁其他玩家的潜兵**、
   **完全不支持 SEAF**、**没有残血优先度**（只有「离弹道最近」），而且锥角/范围环/锁定标记/
   方框/掩体判断/自己绑定这一整套都没有。也就是说你要的优先度顺序会**只剩前两档**。

## 已知限制

- **只在 P-11 治疗剂手枪上生效**，其它武器一律不碰。
- SEAF 只在**带对应词条的星球**上才会出现；没有词条时叫 SEAF 增援会让游戏在
  鹈鹕落地后崩溃，所以 SEAF 那条路不一定每次都测得到。潜兵那条路在双人游戏里随时可测。
- 制导组件的实际转向速度由 P-92 的法令组件决定（出厂 90 m/s 出膛速度、转向 30）。
  **本版本没有实现弹速改写**（cfg 里也没有 `seek_speed`），要调弹速请用
  Guided Rounds 的对应功能。
- 本 mod 与 Guided Rounds **同时启用会互相冲突**：两者都会抢 P-11 的同一行设置。
